# 간병비 조정·금액 확인·재신청

상태: 기존 판단을 사후 정리한 재현 실험용 명세. 이 저장소의 화면 구현·조작 검증은 미실행.

사용자 질문: 지원자가 없으면 무엇을 할 수 있는가? 비율을 고르면 평일·주말 단가와 총금액이 얼마나 바뀌는가? 어느 단계에서 확정되는가?

기존 AI 초안의 정보 밀도를 줄이되, 평일·주말 단가 변화는 선택에 필요하다고 판단해 입력 가까이에 남겼다. 전체 합산 내역은 최종 확인 단계로 분리했다. 이 판단은 [공통 패턴](../patterns.md)에 정리했다.

데이터는 [care-price.json](../../fixtures/care-price.json), 실행 결과는 [검증 기록](../../validation/price-adjustment.md)을 참조한다.

## 필수 요구사항

| ID | 단계 | 요구사항 |
|---|---|---|
| R01 | 매칭 실패 | 지원자가 없는 상태와 금액을 조정해 다시 신청할 수 있는 경로를 안내한다. 지원 가능성의 개선을 보장하지 않는다. |
| R02 | 금액 조정 | 인상률을 선택할 수 있고, 평일·주말의 변경 전후 단가와 예상 총금액이 선택에 따라 갱신된다. |
| R03 | 금액 확인 | 선택한 인상률, 변경 단가, 일수별 간병비, 추가 비용과 총금액을 확인할 수 있다. |
| R04 | 재신청 | 확인 단계의 총금액과 일치하는 금액으로 데모 재신청을 완료한다. 조정 화면에서 바로 확정하지 않는다. |
| R05 | 되돌아가기 | 확인 화면에서 돌아가면 선택값이 유지된다. 확정하지 않고 나가면 실제 신청 금액은 바뀌지 않는다. |
| R06 | 완료 | 최종 확인 화면에 ‘재신청이 완료됐어요.’와 적용 금액을 표시하고 확정 버튼을 비활성화한다. 완료는 로컬 데모 상태이며 실제 결제·지원자 모집·환불은 수행하지 않는다. |

## 화면별 구성과 동작

아래 순서로 배치한다. 일수별 비용·보험료·수수료 상세는 최종 확인 단계에서 보여준다.

| 화면 | 구성 순서와 주요 문구 | 버튼과 이동 |
|---|---|---|
| 매칭 실패 | 헤더 ‘매칭 실패’ → 안내 이미지 → ‘현재 간병비에서는 지원자가 없어요.’ → 금액 조정 후 재신청할 수 있다는 설명 | 하단 ‘금액 조정하기’ → 금액 조정. ‘닫기’와 헤더 X → 진입 전 화면으로 복귀 |
| 금액 조정 | 헤더 ‘금액 조정’ → ‘간병비를 얼마나 올릴까요?’ → ‘금액을 올리면 간병인의 지원 가능성을 높일 수 있어요.’ → 현재 선택 비율 → 초기화·+5%·추천 +10%·+15% → 평일·주말의 변경 전후 단가·각 증가액 → 예상 결제 금액 | 선택 즉시 단가·증가액·총금액 갱신. 하단 ‘변경 금액 확인하기’ → 최종 확인. 뒤로 → 매칭 실패. 헤더 X → 진입 전 화면으로 복귀 |
| 최종 확인 | 헤더 ‘금액 조정’ → ‘변경된 금액을 확인해 주세요.’ → 적용 비율·변경 단가·예상 결제 금액 → 평일·주말 일수별 비용·보험료·플랫폼 수수료 | 하단 ‘{총금액}원으로 재신청하기’ → 데모 완료 상태. 뒤로 → 금액 조정 |

- 현재 선택과 추천 표시는 구분한다. 기본 선택은 +5%이며, +10%의 ‘추천’ 표시는 다른 비율을 선택해도 유지한다.
- 단계 사이에서 뒤로 가면 선택값과 계산 결과를 유지한다. 확인 화면으로 이동하는 것만으로는 신청 금액이 변경되지 않는다.
- X·닫기로 흐름을 종료하면 초안을 버리고 기존 신청 금액을 유지한다. 새로 진입하면 +5%에서 시작한다.
- 최종 확정은 한 번만 적용한다. 완료 시 별도 화면을 추가하지 않고 위 완료 문구와 확정한 총금액을 표시한다.

## 이번 실험에만 사용하는 가정

다음 항목은 인터랙션을 재현하기 위한 고정 조건이며, 원래 서비스의 확정 정책이라고 주장하지 않는다.

| ID | 실험 가정 |
|---|---|
| A01 | 기본 선택은 +5%, 선택지는 +5%·+10%·+15%다. 초기화하면 +5%로 돌아간다. 직접 숫자 입력은 이번 범위에서 제외한다. |
| A02 | 예시 일정은 평일 22일, 주말·공휴일 8일이다. 기본 단가는 각각 90,000원, 108,000원이다. |
| A03 | 보험료는 총 30,000원으로 고정한다. 실험의 플랫폼 수수료는 인상 후 간병비 합계의 10%로 계산한다. |
| A04 | A03의 수수료 공식은 제공된 +5% 화면의 예시 금액을 재현하기 위한 가정이다. 실제 회사 수익 정책을 확인한 결과가 아니다. |
| A05 | 선택 비율은 평일·주말의 원래 단가에 각각 적용한다. 이미 인상된 단가에 다시 누적 적용하지 않는다. KRW 정수로 계산한다. |
| A06 | 검토 단계는 저장 전 초안이다. 최종 버튼을 누르면 로컬 데모 상태만 갱신한다. 중복 누르기로 금액이 중복 적용되지 않는다. |
| A07 | +10%에 ‘추천’을 표시한다. 이번 실험의 고정 추천값이며 추천 알고리즘·효과를 검증한 결과가 아니다. 설명은 ‘10%는 추천 인상률입니다.’로 하고, 노출 증가나 매칭 성공을 보장하는 문구는 사용하지 않는다. |

## 계산 기준

데이터와 기대값의 기준 파일은 `fixtures/care-price.json`이다. 이 표는 사람이 검토하기 위한 요약이다.

| 인상률 | 평일 단가 | 주말 단가 | 간병비 합계 | 수수료 | 보험료 | 총금액 |
|---|---:|---:|---:|---:|---:|---:|
| 0% / 변경 전 | 90,000 | 108,000 | 2,844,000 | 284,400 | 30,000 | 3,158,400 |
| 5% | 94,500 | 113,400 | 2,986,200 | 298,620 | 30,000 | 3,314,820 |
| 10% | 99,000 | 118,800 | 3,128,400 | 312,840 | 30,000 | 3,471,240 |
| 15% | 103,500 | 124,200 | 3,270,600 | 327,060 | 30,000 | 3,627,660 |

이번 값은 실험 데이터다. 실제 환자 이름·주소·일정·결제정보는 사용하지 않는다.

## 작업 범위

이번에는 실패 안내 → 금액 조정 → 최종 확인 → 데모 재신청 완료만 구현한다. 실제 결제·환불·지원자 모집은 연결하지 않는다.

## AI 제작 요청

이 문서와 공통 패턴·디자인 기준을 읽고 모바일 웹 프로토타입을 구현한다. 제공된 fixture를 사용하고 390×844, 360×800 CSS px에서 확인한다. 최초 생성물을 보존한 뒤 검증하고, 실제 컴포넌트 경로·토큰 연결·실행 결과를 기록한다.
