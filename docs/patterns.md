# 금액 변경과 최종 확인 패턴

패턴 ID: P-AMOUNT-01 · 상태: 기존 판단을 사후 정리한 재현 실험용 규칙

## 목적과 적용 조건

사용자가 금액을 바꾸거나 비용이 발생하는 행동을 하기 전에, 변경의 영향과 최종 결과를 이해하도록 돕는다. 간병비 조정·재신청에 우선 적용하고, 추후 결제·환불에 공통 구조를 적용할 수 있을지 따로 검증한다.

## 결정의 근거

| 관찰·판단 | 규칙으로 남길 내용 |
|---|---|
| AI 초기 시안에는 환자 정보, 현재 단가, 입력, 변경 단가 등 여러 정보가 한 단계에 모였다. | 각 단계의 핵심 질문과 직접 관련된 정보부터 보여준다. |
| 정보를 줄이는 과정에서 단가 변화가 총금액 안에 묻힐 수 있었다. | 정보량만 줄이지 않는다. 선택의 영향을 판단하는 데 필요한 값은 입력 가까이에 둔다. |
| 평일·주말의 기본 단가가 다르다. 같은 인상률도 증가액은 다르다. | 각 단가에 같은 비율을 적용하고, 변경 전후와 항목을 함께 보여준다. |
| 상세 합산 내역은 최종 확정 전에 확인하면 된다. | 조정 단계와 검토 단계의 역할을 나누고, 검토 후 확정하게 한다. |

이 근거는 설계 판단이다. 실제 사용자가 더 안심했다거나 과업 성공률이 올랐다는 결과는 별도 검증이 필요하다.

## 규칙

| ID | 규칙 | 필요한 이유 | 적용·검증 위치 |
|---|---|---|---|
| P01 | 조정 단계에서 인상률 선택을 가장 먼저 식별할 수 있게 한다. | 이 화면의 핵심 행동은 비율 선택이다. | 금액 조정 / S01·S02 |
| P02 | 선택 UI 가까이에 평일·주말 단가의 변경 전후와 예상 총금액을 표시한다. | 선택이 단가와 전체 비용에 미치는 영향을 함께 확인한다. | 금액 조정 / S02 |
| P03 | 일수별 비용·보험료·수수료 등 전체 합산 내역은 최종 확인 단계에서 제공한다. | 조정 단계의 입력을 방해하지 않으면서 확정 전에 근거를 확인한다. | 금액 확인 / S03 |
| P04 | 조정 단계의 버튼은 ‘변경 금액 확인하기’, 확정 단계는 ‘{총금액}원으로 재신청하기’로 구분한다. | 이동과 확정의 결과를 다르게 설명한다. | 두 단계 / S01·S04 |
| P05 | 최종 금액은 상세 항목과 구분하고 라벨을 반드시 붙인다. | 강조 색상만으로 총금액·위약금의 의미를 전달하지 않는다. | AmountSummary / S03·S07 |
| P06 | 단가·소계·총금액·버튼 금액은 같은 계산 결과를 사용한다. | 화면마다 계산이 달라지는 오류를 막는다. | 공통 계산 경로 / S02·S03·S04 |
| P07 | 뒤로 가기에서는 초안을 유지하고, 확정하지 않고 나가면 신청 금액을 바꾸지 않는다. | ‘확인’만 한 행동이 금액 변경으로 이어지지 않게 한다. | 이동·확정 상태 / S05·S06 |

## 좋은 예시와 피할 예시

| 좋은 예시 | 피할 예시 |
|---|---|
| +5% 선택 아래에 ‘평일 90,000 → 94,500원 / 주말 108,000 → 113,400원’을 보여준다. | 두 단가 모두 +4,500원으로 표시하거나 총금액만 보여준다. |
| 선택 결과를 먼저 확인하고, 다음 화면에서 22일·8일 비용과 추가 비용을 확인한다. | 입력 위에 전체 환자 정보와 모든 비용 내역을 펼쳐 핵심 입력을 밀어낸다. |
| ‘변경 금액 확인하기’ 다음에 총금액이 명시된 확정 버튼을 둔다. | 조정 화면과 검토 화면 모두 ‘재신청하기’여서 어느 단계에서 확정되는지 불명확하다. |
| ‘지원 가능성을 높일 수 있어요’처럼 가능성으로 안내한다. | 근거 없이 ‘반드시 매칭돼요’, ‘10%면 더 많이 노출돼요’라고 보장한다. |

## 토큰과 컴포넌트의 역할

- 토큰: 금액·본문·구분선·주요 행동을 어떤 시각적 의미로 표현할지 정한다. 계산이나 위약금 비율을 담지 않는다.
- 컴포넌트: 단가의 변경 전후, 금액 항목, 최종 합계를 반복 가능한 구조로 만든다.
- 이 패턴: 그 컴포넌트를 **언제, 어디에, 어떤 정보와 함께** 사용하는지 정한다.

## 다른 흐름에 적용할 때

결제는 결제 총액과 포함 항목, 환불은 차감 항목과 환불 예정액을 확정 전에 보여준다는 구조를 공유할 수 있다. 다만 결제액·환불액·위약금은 의미가 다르다. 같은 카드 모양을 쓴다는 이유로 제목·강조 의미·확정 동작을 같게 만들지 않는다. 실제 확장 구현과 검증은 현재 미실행이다.
